# Bulk H4 — cobertura y reproducción HTTP

## Contrato y alcance

Base normativa consultada: OpenAPI `0.6.0-rc.3` en Docs `master` (`f903f0bb0485bc0c6a6a7c6545446e972286daf6`), AsyncAPI `0.6.0-rc.4` y SPEC-001. Las rutas de importación son provisionales internas (`x-status: provisional-internal`) y requieren `userBearer`. La admisión responde `202`; no significa que Catalog, Pricing e Inventory hayan terminado.

La admisión usa `multipart/form-data`, campo binario obligatorio `archivo` y `template_version` opcional, cuyo único valor admitido es `2`. Incluye `x-correlation-id` como UUID conforme al parámetro común. La respuesta `ImportacionGeneralAceptada` requiere `batch_id`, `status: QUEUED`, `template_version` y `correlation_id`. Los límites H4 son 10 485 760 bytes por archivo, 5 000 filas de datos y 50 MiB XLSX descomprimido. Fuentes: [OpenAPI](https://github.com/Taller-SW-Web/G6-Productos-Ofertas-docs/blob/master/contratos/http/openapi.yaml), [AsyncAPI](https://github.com/Taller-SW-Web/G6-Productos-Ofertas-docs/blob/master/contratos/eventos/asyncapi.yaml), [acuerdos internos H4](https://github.com/Taller-SW-Web/G6-Productos-Ofertas-docs/blob/master/arquitectura/decisiones/ACUERDOS-INTEGRACION-INTERNA-G6-H4.md) y SPEC-001. OpenAPI vigente consultado: `0.6.0-rc.3`; AsyncAPI: `0.6.0-rc.4`, addendum Bulk v2 del 03/11/2026.

DEC-G6-INT-08 y 09 rigen la plantilla v2, resultados durables por fila/dominio y la exclusión de inventar éxito para dominios pendientes. DEC-G6-INT-10 rige la exportación y queda fuera de este cierre de importación. Los acuerdos internos están aprobados para G6; no equivalen a homologación externa ni a grants G7. Esta ampliación no cambia contratos compartidos.

El nuevo proceso Gateway→Bulk→Catalog pasa localmente en el SHA de trabajo: consulta de plantillas CSV/XLSX (`200`), admisión (`202`) con correlación preservada, consulta de resultado durable, descarga de reporte tras fallo Catalog y rechazo de reanudación inválida (`409 IDEMPOTENCY_CONFLICT`). El ejercicio también comprueba Outbox, replay de RabbitMQ y deduplicación Inbox. Esta evidencia cierra la ruta local por Gateway de #96; no demuestra autenticación G7, CORS de navegador, Supabase real ni despliegue.

### Hallazgos transversales

- `apps/bulk-svc/src/bulk-svc.http.spec.ts` cubre multipart CSV, `202`, consulta/reporte/reanudación con dobles, error de formato, archivo no admitido y 10 485 761 bytes (`413`). La ampliación añade HTTP XLSX y rutas conectadas a PostgreSQL local descartable.
- `bulk.repository.integration.spec.ts` ya cubre PostgreSQL 17, integridad de lote, Outbox/Inbox, resultados idempotentes, resultados parciales, reconciliación, requeue e invariantes; las pruebas no atraviesan el controlador HTTP.
- `BulkStorageService` ya verifica bucket privado, carga/lectura/reintento y colisión mediante `fetch` simulado. No hay integración contra Supabase real ni bucket de pruebas autorizado.
- `run-bulk-joint-v2-local.mjs` conserva los casos v1/v2 y añade el recorrido real cliente→Gateway→Bulk→Storage local→PostgreSQL/Outbox→RabbitMQ→Catalog→Inbox Bulk→consulta Gateway. Verifica Outbox, resultado Catalog persistido, Inbox y Catalog sin duplicados tras replay. Gateway y Bulk son procesos separados ligados a loopback; Catalog ejecuta su consumidor real en el proceso aislado de su suite E2E.
- Las pruebas unitarias cubren 5 000/5 001 filas y XLSX con expansión superior a 50 MiB. La prueba HTTP aislada cubre 10 485 761 bytes (`413`).
- El modo `RESTRICTED_DEMO` se habilita solo en los procesos efímeros: Gateway acepta el peer TCP de loopback y Bulk permite solo `127.0.0.1`. El preload del harness liga el listener Gateway a `127.0.0.1`; el código de Gateway no se modifica. La segunda ejecución apaga demo y comprueba `401 TOKEN_INVALIDO` sin token. No se fabrican identidades ni tokens G7.
- No se prueba `403 SCOPE_INSUFICIENTE` porque no se dispone de grants/credenciales G7 y no se simula un actor; tampoco se prueban CORS en navegador, Supabase real, perímetro desplegado ni E2E Oracle. Esos estados permanecen pendientes.

## Reproducción

La prueba HTTP/PostgreSQL usa NestJS `BulkSvcModule`, repositorios Drizzle y PostgreSQL 17 descartable. El `BulkUserBearerGuard` real valida un JWT RS256 firmado con una clave generada para esa prueba, audiencia `api-productos` y rol `GESTOR_COMERCIAL`; esto valida el guard y la ruta autenticada, pero no acredita una identidad ni configuración G7 real. El servicio de almacenamiento usa `BulkStorageService` real contra un servidor HTTP local que emula las respuestas mínimas de Supabase Storage; esto **no** es una integración con Supabase.

Comandos reproducibles desde la raíz del backend:

```powershell
npm test -- apps/bulk-svc/src/domain/bulk-template-v2.spec.ts
npm run test:e2e -- apps/bulk-svc/test/bulk-postgres-outage.e2e-spec.ts
$env:PATH = 'C:\Program Files\Git\usr\bin;' + $env:PATH
node apps/bulk-svc/test/support/run-bulk-joint-v2-local.mjs
```

El runner acepta un filtro Vitest opcional para depuración, por ejemplo `node apps/bulk-svc/test/support/run-bulk-joint-v2-local.mjs 'BULK-JOINT v2'`. La ejecución sin filtro corre el caso conjunto anterior y el nuevo flujo Gateway→Bulk→Catalog.

La prueba PostgreSQL inicia una instancia desechable, carga la copia del fixture `test/fixtures/0001_create_bulk_persistence.sql` desde la migración oficial inmutable y elimina contenedores/archivos temporales al salir. Usa el módulo Nest real, repositorios Drizzle reales y `BulkUserBearerGuard` con JWT RS256 generado localmente para la prueba. Storage usa un servidor local compatible con las respuestas necesarias; no es Supabase. La prueba conjunta crea un peer temporal solo en `127.0.0.1`, activa flags de demo restringidos únicamente dentro de ese proceso efímero, y conecta Bulk real con PostgreSQL TLS, RabbitMQ y Catalog. No abre listener externo ni valida identidad G7.

## Estados externos y fuera de alcance

- Inventory `inventory.bulk.stock.adjust.requested`: owner Inventory/Taco; afecta solo el ajuste de stock inicial; se desbloquea con contrato AsyncAPI aprobado y prueba bilateral provider/consumer. La importación y resultados CATALOGO continúan de forma independiente.
- Exportación: owner Bulk/Castilla; afecta lecturas consolidadas; se desbloquea con proveedores autorizados de Catalog/Pricing/Inventory y evidencia de snapshot conforme DEC-G6-INT-10. No se presenta como funcional aquí.
- JWT G7: owner G7/Seguridad; afecta la autorización autenticada real; se desbloquea con issuer/JWKS, audiencia, rol/scope y grant efectivos más pruebas positivas y negativas. Los tests locales no sustituyen esos datos.
- Supabase de prueba: owner Marco/infraestructura; afecta validación contra el servicio real; se desbloquea al autorizar un proyecto/bucket privado descartable y sus credenciales restringidas. La API-compatible local solo acredita el adaptador.
- Gateway producción/despliegue: owner Gateway/Marco (#21); afecta la ruta desplegada y su configuración de perímetro; se desbloquea con URL/entorno privado autorizado y evidencia sobre SHA/digest. La ruta local de procesos separados ya está probada con demo restringido de loopback; no concede grants ni homologación.

La cobertura restante de #90 (reglas), #91 (consultas), #92 (escrituras) y #93 (AMQP) se limita a criterios no acreditados por las pruebas enumeradas aquí. #95 requiere la integración real frontend→Gateway; no está en ownership de esta entrega.
